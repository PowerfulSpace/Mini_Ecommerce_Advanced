# ADR-006: Частичный checkout и частичная отмена

- **Статус:** Принято
- **Дата:** 2026-10-26

## Контекст

Сейчас checkout оформляет всю корзину, а отмена возвращает весь заказ. Для
сценариев «купить только часть корзины» и «отменить часть позиции» этого
недостаточно.

Нужно определить:

- как пользователь выбирает позиции корзины;
- как выбор влияет на checkout, резервы и очистку корзины;
- как отменять количество внутри позиции заказа;
- как сохранять историю отмен, не меняя снимок `OrderItem.Quantity`;
- как защищать частичную отмену от конкурентных и повторных запросов;
- как частичная отмена взаимодействует с резервами, оплатой и refund.

## Решение

### Выбор позиций корзины

`CartItem.IsSelected` (`bool`, по умолчанию `true`) является частью состояния
корзины.

Выбор изменяется через:

```http
PUT /api/cart/selection
If-Match: "<cart rowversion>"

{
  "items": [
    { "productId": "...", "isSelected": true }
  ]
}
```

- Запрос обновляет перечисленные позиции; позиции, отсутствующие в `items`,
  сохраняют текущее значение.
- Изменение выбора — мутация корзины: требует `If-Match` и изменяет
  `rowversion` корзины.
- Новые и существующие позиции по умолчанию имеют `IsSelected = true`;
  миграция существующих данных устанавливает `true`.
- Выбор сам по себе не резервирует запас. Резерв создаётся только на checkout.

`GET /api/cart` возвращает:

- `isSelected` для каждой позиции;
- `totalAmount` — стоимость всей корзины;
- `selectedTotalAmount` — стоимость выбранных позиций.

### Частичный checkout

Checkout оформляет только выбранные позиции:

- читает и проверяет только выбранные позиции;
- резервирует только выбранные позиции;
- создаёт заказ и снимки только по выбранным позициям;
- очищает только выбранные позиции.

Невыбранные позиции остаются в корзине без резерва.

Если ни одна позиция не выбрана, checkout возвращает `409 Conflict` с кодом
`cart_empty`; `detail` уточняет, что нет выбранных позиций. Отдельный код для
пустого выбора не вводится.

Fingerprint checkout не включает selection явно. `IsSelected` меняет
`rowversion` корзины, а `rowversion` уже входит в `If-Match` и в fingerprint.
Дублировать selection в fingerprint не нужно.

### Частичная отмена

Эндпоинт:

```http
POST /api/orders/{id}/cancel
If-Match: "<order rowversion>"

{
  "items": [
    { "orderItemId": "...", "quantity": 1 }
  ]
}
```

- Тело необязательно. Отсутствие тела означает полную отмену заказа.
- Если тело содержит `items`, выполняется частичная отмена перечисленных
  количеств.
- Пустой массив `items: []` не является полной отменой и отклоняется как ошибка
  валидации.
- `quantity` должна быть положительным целым числом и не превышать оставшееся
  количество позиции.
- `OrderItem.Quantity` — неизменяемый снимок и не уменьшается.
- Для каждой отмены создаётся запись `OrderItemCancellation`:
  - `Id`;
  - `OrderItemId`;
  - `Quantity`;
  - `CancelledAtUtc`;
  - `Reason?`.
- `OrderItem.CancelledQuantity` вычисляется как
  `SUM(OrderItemCancellation.Quantity)` и не хранится отдельным полем.
- Инвариант: `SUM(CancelledQuantity) <= OrderItem.Quantity`.

`Order.TotalAmount` остаётся снимком исходного заказа. Стоимость отменённой
части вычисляется по снимкам `OrderItem.UnitPrice` и количеству отмены; refund
выполняется по ADR-008.

### Полная и частичная отмена

- Если все позиции заказа отменены на полное количество, заказ переходит в
  `Cancelled` через `Cancel()` (ADR-004).
- Если отменена только часть, статус заказа не меняется; «частично отменён»
  вычисляется по наличию записей `OrderItemCancellation`.
- Полная отмена без тела также переводит заказ в `Cancelled`.
- Отмена заказа в `Cancelled` возвращает `409 Conflict` с кодом
  `order_already_cancelled`.
- Отмена заказа в `Returned`, `Shipped` или `Delivered` возвращает `409 Conflict`
  с кодом `invalid_order_transition`.
- Отмена не изменяет корзину.

### Запас и оплата

- Отмена до оплаты (`Created`): отменяемое количество возвращается из `Reserved`
  в `Available`.
- Отмена после оплаты (`Paid`): `Reserved` уже consumed; отменяемое количество
  возвращается в `Available`, а refund выполняется по ADR-008.
- Если refund завершается неудачно, транзакция отмены откатывается: заказ,
  отмены, запас и платёж не должны остаться в частично изменённом состоянии.

### Идемпотентность и конкурентность

- Отмена защищается `If-Match` на версии заказа (`Order.RowVersion`), а не
  `Idempotency-Key`.
- `Order.RowVersion` — новое поле; успешная полная или частичная отмена изменяет
  его.
- Устаревший `If-Match` возвращает `412 Precondition Failed`; стабильный код
  конфликта версии заказа должен быть определён в `api.md` (№16).
- Полная и частичная отмена должны выполняться в транзакции с блокировкой строки
  заказа и атомарными изменениями запаса.
- Строки товаров блокируются в стабильном порядке, предпочтительно по
  `ProductId`.
- Повторная или конкурентная отмена не должна возвращать запас или делать refund
  дважды.
- Если после отмены всех позиций заказ становится `Cancelled`, повторная отмена
  возвращает `order_already_cancelled`.

## Последствия

### Преимущества

- Пользователь может оформить только нужные позиции.
- Невыбранные позиции не теряются и не резервируются.
- История частичных отмен сохраняется без изменения снимка количества.
- Полная отмена остаётся совместимой с существующим сценарием.
- Конкурентные отмены защищены версией заказа и транзакцией.

### Компромиссы

- Появляется новое состояние выбора в корзине и новый эндпоинт.
- Нужны `Order.RowVersion`, `OrderItemCancellation` и вычисляемый
  `CancelledQuantity`.
- Частичная отмена после оплаты зависит от refund в ADR-008.
- `Order.TotalAmount` не пересчитывается; клиенту нужно вычислять сумму отмены
  отдельно.
- Пустой `items: []` и отсутствие тела имеют разную семантику.

### Что не делаем

- Не вводим `Idempotency-Key` для отмены.
- Не уменьшаем `OrderItem.Quantity`.
- Не храним `CancelledQuantity` отдельным полем.
- Не вводим отдельный статус `PartiallyCancelled`.
- Не добавляем частичный возврат после доставки в этом ADR.

## Требования к реализации

- Добавить `CartItem.IsSelected` (`bool`, default `true`) и миграцию существующих
  позиций в `true`.
- Реализовать `PUT /api/cart/selection` с `If-Match`; изменение выбора должно
  менять `rowversion` корзины.
- Обновить `GET /api/cart`: `isSelected`, `totalAmount`,
  `selectedTotalAmount`.
- Checkout должен читать, резервировать и очищать только выбранные позиции;
  пустой выбор возвращает `cart_empty` с уточняющим `detail`.
- Не включать selection в fingerprint checkout явно; использовать `If-Match`.
- Добавить `OrderItemCancellation` и вычисляемое `CancelledQuantity`.
- Реализовать полную и частичную отмену с проверкой количества и инварианта
  `SUM(CancelledQuantity) <= OrderItem.Quantity`.
- Добавить `Order.RowVersion` и требовать `If-Match` для отмены.
- Выполнять отмену, изменение запаса и refund в согласованной транзакции.
- Добавить тесты на:
  - выбор позиций и `If-Match`;
  - checkout только выбранных;
  - пустой выбор;
  - частичную отмену;
  - полную отмену через все количества;
  - повторную и конкурентную отмену;
  - отмену до и после оплаты;
  - сохранение снимка `OrderItem.Quantity`;
  - вычисление `CancelledQuantity`.
