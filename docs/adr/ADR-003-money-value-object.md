# ADR-003: Money value object

- **Статус:** Принято
- **Дата:** 2026-10-26

## Контекст

В текущей модели денежные значения представлены обычным `decimal`:
`Product.Price`, стоимости строк и итоги корзины, `Order.TotalAmount`,
`OrderItem.UnitPrice` и `Payment.Amount`. Такой `decimal` не несёт валюту,
правило округления и доменные инварианты.

Из-за этого возможны:

- случайное смешивание валют;
- отрицательные денежные значения;
- несогласованное округление в разных местах;
- переполнение при сохранении в `decimal(18,2)`;
- использование `double` или `float` вместо денежного типа.

В MVP+ поддерживается только `USD`. База данных уже использует
`decimal(18,2)`, а API отдаёт денежные значения числом. Новый тип не должен
ломать эти контракты.

## Решение

Ввести неизменяемый value object `Money`:

- `Amount` — `decimal`;
- `Currency` — валюта, в MVP+ допускается только `USD`;
- сравнение и арифметика учитывают валюту;
- объект создаётся только через контролируемую фабрику/конструктор.

`Money` используется во всём Domain для денежных значений:

- `Product.Price`;
- стоимости строк и итоги корзины;
- `Order.TotalAmount`;
- `OrderItem.UnitPrice`;
- `Payment.Amount`.

### Границы Domain, EF и API

- **Domain:** деньги представлены только `Money`, а не «сырым» `decimal`.
- **EF Core:** используется value converter `Money` ↔ `decimal(18,2)`.
  `Currency` не персистится, потому что в MVP+ всегда `USD`.
- **API:** денежное значение сериализуется как число (`decimal`), без объекта
  `{ "amount": ..., "currency": ... }`. Контракт API не меняется.

### Округление

Округление выполняется в `Money` при создании значения:

- до двух знаков после запятой;
- режим `MidpointRounding.AwayFromZero`;
- стоимости строк и итоги не округляются повторно: они складываются из уже
  созданных `Money`-значений.

Умножение `Money` на целое количество допускается для расчёта стоимости строки
или итога; результат проходит те же проверки и округление при создании `Money`.

### Инварианты

- `Amount >= 0`.
- `Currency == USD`.
- Сложение и вычитание разрешены только для одинаковой валюты; при несовпадении
  валют выбрасывается `DomainException`. В MVP+ валюты всегда совпадают, но guard
  сохраняется.
- Значение должно помещаться в `decimal(18,2)`. При переполнении выбрасывается
  `DomainException`; нельзя полагаться на усечение или округление SQL Server.

Конкретные коды ошибок API для нарушений `Money` определяются в `SPEC.md` и
`api.md`. Этот ADR фиксирует только доменное поведение и тип исключения.

## Последствия

### Преимущества

- Денежные значения получают единый тип и единые инварианты.
- Округление централизовано и не зависит от места расчёта.
- Смешивание валют и отрицательные суммы обнаруживаются в Domain.
- Переполнение `decimal(18,2)` обнаруживается до сохранения.
- API и существующая схема `decimal(18,2)` не ломаются.

### Компромиссы

- Все денежные поля Domain нужно перевести на `Money`.
- Требуется EF value converter и маппинг в DTO.
- `Currency` не хранится в базе, поэтому схема не готова к мультивалютности.
- Сериализация в API остаётся числом, то есть валюта не передаётся явно.

### Что не делаем

- Мультивалютность, курсы валют и конвертацию.
- Колонку `Currency` в базе данных.
- Объект `{ amount, currency }` в API.
- `double`/`float` для денег.
- Отдельное округление каждой строки и итога после сложения.

## Требования к реализации

- Разместить `Money` в Domain как неизменяемый value object.
- Не допускать создания `Money` с отрицательным `Amount`, не-USD валютой или
  значением вне диапазона `decimal(18,2)`.
- Реализовать сложение, вычитание и умножение на целое количество с проверкой
  валюты и переполнения.
- Настроить EF Core value converter `Money` ↔ `decimal(18,2)` в Infrastructure;
  Domain не должен зависеть от EF Core.
- В Application/DTO и API отдавать `Money.Amount` как `decimal`; не добавлять
  `currency` в JSON.
- Сохранить точность `decimal(18,2)` в SQL Server.
- Добавить тесты на округление `AwayFromZero`, отрицательные значения,
  несовпадение валют, переполнение, сложение/умножение и round-trip через EF Core.
- Согласовать использование `Money` в `Product`, корзине, заказе и платежах с
  ADR-004, ADR-005 и ADR-008.
